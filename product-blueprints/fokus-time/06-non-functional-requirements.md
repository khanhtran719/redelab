## Current feasibility evidence

Prior [platform report](../../sessions/2026-11-21-01-fokus-time/05-platform-feasibility.md) supports a manual local loop as INFERENCE, not tested behavior. Targeted22/11 refresh by Technical reviewer: [Android Auto Backup](https://developer.android.com/identity/data/autobackup) and [Apple iCloud Backup contents](https://support.apple.com/en-us/108770), access22/11/2026; primary documents indicate app data may participate in OS backup. Details/limits in [technical initial](reviews/technical-initial.md). That is documentation evidence, not proof Fokus backup/restore works. No market research rerun.

No timer, notifications, Screen Time/UsageStats/Accessibility blocking, camera/mic or cross-device sync requirement enters this baseline. Such capabilities were conditional/unverified previously; excluding them avoids requiring an unsupported API. Accessibility of the UI is mandatory quality, distinct from using Android AccessibilityService for blocking.

## Product-level risks and future investigation

- **Quality of self-assessment:** rubric/attempt truth unknown; software verifies only declarations and guards. User research/learning outcomes need separate authorized studies; no engine added to solve this.
- **OS backups:** old snapshots can restore deleted/withdrawn content; clear current-dataset deletion copy is essential. Actual platform configuration/disclosures must match tested behavior.
- **Durability:** real storage-full, partial failure, duplicate/stale UI, process death, update and corruption need tests with an independent saved-state oracle; no framework/database mandated.
- **Shared/unlocked devices:** local text may be visible to someone holding an unlocked device; no invented account isolation. Use existing OS protections, verify no content exposure in support/logs; future authentication would require separate product scope.
- **Age/jurisdiction/content rights:** no legal clearance; intended primary user university student, not a separate minors/parental product. Store privacy/content requirements need product-specific review before publication, not an invented gate for writing this specification.
- **Support/performance:** OS versions, devices, dataset profile and limits remain explicit qualification decisions; they do not permit Dev Studio to silently weaken business rules. Device experiment/build is not authorized by this document.

No device, network/privacy, save/recovery, assistive-technology, store, legal or performance test has run on a Fokus application. Passing specification audit later establishes clarity/traceability only.
