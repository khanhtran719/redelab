# Adversarial Review

## Trigger and purpose

Use for independent OPPORTUNITY review or authorized SPECIFICATION review; not a substitute for QA execution.

## Inputs

Frozen current candidate/spec revision, strongest supporting case, source/claim ledger, actual debate, Founder limits.

## Procedure

1. Determine mode. OPPORTUNITY: demand, substitute, distribution, payment, dependency, differentiation. SPECIFICATION: contradictory requirements, state gaps, recovery, testability and unauthorized scope.
2. First steelman the strongest supporting case; independently inspect consequential evidence, not just a selectively shortened CIO summary.
3. Classify finding as EVIDENCED_BLOCKER / CONDITIONAL_RISK / EVIDENCE_GAP / SPECIFICATION_DEFECT; track separate severity and status.
4. State concrete causal failure mechanism, evidence/uncertainty, impact, falsifier or proposed correction and a result that would reduce concern.
5. Obtain actual proponent response to material objections, preserve disagreement and revise your own judgment when supported.
6. Mark RESOLVED only after checking the exact corrected artifact or new evidence, never merely a promised fix.

## Required output

Prioritized register with affected IDs, evidence, strongest counter-case, objection, rebuttal, changed assessment, verified status and unresolved blockers.

## Evidence and uncertainty

Apply [evidence policy](../../../protocols/evidence-policy.md). Classify material empirical claims VERIFIED / INFERENCE / HYPOTHESIS / UNKNOWN; label other behavioral or technical verification dimensions separately. Cite claim/source IDs and dates where material. Use the compact [finding and assignment contract](../../../protocols/agent-contracts.md) when invoked by a council; do not replace actual reasoning with checkboxes.

## Failure conditions

Missing frozen baseline, inaccessible substantive evidence or no real response: mark PARTIAL/NOT_RUN; do not invent a completed review.

## Authorization and collaboration

No unauthorized external outreach, attack execution, code or build. Cross-department review follows [protocol](../../../protocols/cross-department-review.md).
